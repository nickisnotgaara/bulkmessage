# Сервисы массовых рассылок с фермой аккаунтов и передачей лидов

> Источники: официальные сайты сервисов, отраслевые обзоры (cossa.ru, unisender, crmchat.ai, otzyvmarketing.ru, maxsurge, max-catalog24, shutok, darktelegram, gopulsar, timeweb, vakas, accs-shop), кейсы клиентов.
> Дата сбора: 16.09.2026. Цены и фичи меняются — сверяйся на сайтах.

---

## 1. Какой паттерн ищем

Пользовательский запрос: **«сервисы как molnio.ru — много аккаунтов, при бане одного подключают другой, заинтересованных лидов через бота отправляют в основной аккаунт»**.

Разложим по слоям:

```
┌──────────────────────────────────────────────────────────┐
│  Слой 1. ФЕРМА АККАУНТОВ (или облако)                    │
│  • прогрев, прокси, fingerprint, MTProto/Wazzup сессии   │
│  • ротация при бане / cooldown / FloodWait               │
├──────────────────────────────────────────────────────────┤
│  Слой 2. АНТИБАН / SMART-РАССЫЛКА                        │
│  • паузы 60–300 сек, человеческие задержки               │
│  • спинтакс / AI-уникализация текстов                    │
│  • per-account daily cap + hour window                   │
├──────────────────────────────────────────────────────────┤
│  Слой 3. AI / BOT QUALIFICATION                          │
│  • автоответ на входящие                                 │
│  • квалификация лида (квалификационные вопросы)          │
│  • оценка «горячий / холодный»                           │
├──────────────────────────────────────────────────────────┤
│  Слой 4. HANDOFF К ЖИВОМУ МЕНЕДЖЕРУ                      │
│  • передача лида + история переписки                     │
│  • лид → в CRM (amoCRM, Bitrix24) / Telegram-бот / Slack │
│  • единое окно диалогов (все аккаунты в одном inbox)     │
└──────────────────────────────────────────────────────────┘
```

Все найденные сервисы реализуют ту или иную часть. Ниже — карта.

## 4. Что общего у топовых сервисов (best practices)

Из обзоров crmchat.ai, wsender.ru, gopulsar.ru, maxsurge.ru, darktelegram.pro, otzyvmarketing.ru:

1. **Прогрев обязателен.** Минимум 2-3 недели перед массовой рассылкой. Автоматизированный прогрев через twin-диалоги между аккаунтами пула.
2. **Per-account прокси.** Каждый аккаунт = отдельный резидентский/мобильный прокси, желательно той же геозоны. 3-5 USD/мес за прокси.
3. **Лимиты per-account:**
   - Новые аккаунты (до 30 дней): 15-20 сообщений/день
   - Прогретые (30-90 дней): 30-50/день
   - Зрелые (90+ дней): 50-80/день
   - **MAX Personal: 3-5 холодных → бан после жалоб**
4. **Спинтакс / AI-уникализация** — менять приветствие, первое предложение, финальный CTA.
5. **Каскад каналов** (TG → MAX → SMS) увеличивает доставляемость до 80%+.
6. **Платный лимит = 50 холодных в день на аккаунт**, выше — экспоненциальный рост риска.
7. **Pause on complaint**: при первой жалобе — авто-pause аккаунта на cooldown.
8. **Передача лида в CRM** с историей переписки — must have. Не «отправил email с контактом», а **deep-link в диалог**.

| Критерий | Вопрос | На что смотреть |

## 6. Compliance / Риски

> Не игнорируй — это база для решения «использовать или нет».

1. **152-ФЗ (РФ):** для холодной рассылки нужно **согласие получателя**. Без согласия — это персональные данные, обрабатываемые без правового основания.
2. **Чёрные списки Роскомнадзора:** если номер попал в реестр — рассылка на него прямо запрещена.
3. **Правила мессенджеров:** WhatsApp Business API имеет жёсткие правила шаблонов. Telegram — неофициальная позиция по автоматизации (формально не запрещена, но при жалобах бан).
4. **Качество базы:** купленные базы часто содержат мёртвые номера, что увеличивает bounсe rate и стоимость доставки.
5. **Репутационные риски:** спам-сообщения в TG/MAX порождают волну негатива в чатах, потерю бренда.

> Molnio прямо пишет: «Каскад доставки: пишем туда, где клиент отвечает. Не доставлено — автоматически идём в следующий канал.» — это про **холодную базу недозвонов**, где контакт когда-то оставил заявку. То есть формально с согласием.

## 7. Рекомендация для проекта bulkmessage

> Если ты хочешь **внедрить** этот паттерн в свой `bulkmessage` проект (Python-стек), а не просто использовать внешний сервис:

### Ключевые компоненты, которые можно взять из реальных сервисов:

1. **Account Pool** (как у OneDash, IntellectDialog):
   - N аккаунтов с per-account proxy
   - Per-account daily limit (например, 15 для нового, 50 для прогретого)
   - При жалобе → 24ч cooldown, потом re-check
   - Авто-pause при достижении порога жалоб

2. **Smart Rotation** (как OneDash):
   - Распределяет нагрузку так, чтобы каждый аккаунт не превышал лимит
   - Помнит, какой аккаунт писал какому контакту (follow-up с того же)
   - Прогрев новых аккаунтов: день 1-2 = 0 msgs, день 3 = 2, ... день 7 = 15

3. **Handoff** (как Molnio, Viora, AI Outreach):
   - AI квалифицирует (LLM API: OpenAI / Anthropic / DeepSeek / GigaChat)
   - Hot lead → в TG-бот менеджеру с deep-link на диалог
   - История переписки передаётся в CRM (amoCRM/Bitrix24)

4. **Channel Cascade** (как Molnio, Flomni):
   - TG → MAX → SMS
   - Если в течение N часов нет ответа в TG → пробуем MAX
   - Если и там нет → SMS-фолбэк (через SMS-провайдер)

### Что готово из `bulkmessage` уже сейчас
- ✅ `state.channel_has_quota()` — квота per-channel
- ✅ `get_sent_phones()` — защита от дублей

### Что **стоит достроить**, если хочешь свою ферму
1. **Account Pool**: добавить сущность «аккаунт» с полями `phone/session_id/proxy_id/state/cooldown_until`
2. **Rotation logic**: новый модуль `farm/rotation.py` — выбор аккаунта на отправку по лимитам
3. **Warmup scheduler**: фоновый процесс, имитирующий человеческую активность
4. **Webhook endpoint**: Flask/FastAPI-сервис, принимающий входящие от всех подключённых каналов
5. **AI-квалификатор**: интеграция с LLM API для оценки сообщения «горячий/холодный»
6. **Handoff-бот**: TG-бот для менеджера (python-telegram-bot / aiogram), принимающий лидов

### Что **не делай**, если не уверен
- ❌ Не покупай «ферму» аккаунтов с рук — 95% это скам или уже забаненные.
- ❌ Не спамь по холодной базе без сегментации — даже Molnio/Viora подчёркивают, что работают с **недозвонами** (было согласие на заявку).
- ❌ Не используй Telegram-сессии с чужих устройств — fingerprint расходится с session, бан в течение часов.

## 9. Короткий вердикт

> Если ты хочешь **быстро** запустить рассылку по базе с автоматической ротацией и AI-квалификацией — **Molnio** или **MaxSurge** (если фокус MAX).
>
> Если хочешь **свой технический стек** в проекте bulkmessage — строй Account Pool + Rotation + AI-квалификатор + Handoff-бот. Архитектура выше — отправная точка.
>
> Если хочешь **TG-рассылку «под ключ»** с ротацией купленных аккаунтов — **AI Outreach** или **IntellectDialog**.
>
> Если нужен **дешёвый старт** (≤ 500 сообщений в день) и контроль руками — **WSender** (700 ₽/мес) или **SenderMax** (MAX).

В любом случае: **без прогрева аккаунтов и per-account прокси ничего работать не будет**. Это базовая инвестиция — минимум 2-3 недели прогрева + 3-5 USD/мес за прокси на каждый аккаунт.
